## ПРОМТ 2. Микрофон локально (1 день, 0 ₽)

```
{общий блок}

ЗАДАЧА 2: МИКРОФОН ЛОКАЛЬНО — ПОЛОСКА ГРОМКОСТИ
Напиши один файл mic_test.html.
ТРЕБОВАНИЯ
- AudioContext создаю строго в обработчике клика (браузеры не дают звук
  без жеста пользователя). При повторном клике — resume(), а не новый контекст.
- getUserMedia({ audio: true }) → AnalyserNode (fftSize 2048).
- Раз в 50 мс читаю getFloatTimeDomainData и считаю RMS = sqrt(среднее(x^2)).
- На экране: вертикальная полоска громкости (высота = RMS с плавным сглаживанием,
  чтобы не дёргалась) и числовое значение в консоль.
- Обработка ошибок: NotAllowedError → экран «Доступ запрещён. Как включить:
  иконка замка в адресной строке → Разрешить микрофон → перезагрузить»;
  отсутствие getUserMedia → «браузер слишком старый».
- Никакой записи в файл, никакой отправки: звук умирает в памяти. Подпиши это
  комментарием в коде рядом с getUserMedia.

ПРИЁМКА: я открываю страницу через Live Server, жму кнопку, разрешаю микрофон.
Скажу тихое «хи» — полоска чуть поднимается. Рассмеюсь — прыгает высоко.
Молчу — полоска опускается почти до нуля через 1–2 секунды.
ЧАСТЫЕ ПРОВАЛЫ: не открыть через Live Server (file:// не даст микрофон) —
если у пользователя ошибка, первым делом проверь, как он открывает страницу.
```

## ПРОМТ 4. Главная разведка: микрофон в iframe Яндекса (1–2 дня, 0 ₽)

```
{общий блок}

ЗАДАЧА 4: ПРОВЕРКА МИКРОФОНА В IFRAME ЯНДЕКС ИГР
Это самая важная проверка проекта. Кросс-доменный iframe блокирует микрофон
по умолчанию; доступ даёт только атрибут allow="microphone" у фрейма, а его
ставит платформа, не я. Если Яндекс его не ставит — вся игра должна
перестраиваться на кнопку-дублёр, поэтому узнать это надо ДО раундов.
ЧТО НУЖНО
1. Минимальный index.html (одна страница, в корне архива):
   - подключение SDK Яндекса: <script src="https://yandex.ru/games/sdk/v2">
     с обработкой ошибки: если YaGames не определён (локальный запуск) —
     выводим «Локальный режим, SDK недоступен» и продолжаем работать;
   - после инициализации SDK вызвать ysdk.features.LoadingAPI?.ready();
   - определить, что мы внутри iframe: window.self !== window.top;
   - кнопка «Проверить микрофон» → getUserMedia({ audio: true }):
     успех → зелёная надпись «МИКРОФОН В IFRAME РАБОТАЕТ» + полоска громкости;
     NotAllowedError → красная надпись «Микрофон заблокирован платформой»;
     любая другая ошибка → её текст и название на экране.
   - все шаги логировать в консоль с префиксом [PROIV] — по логу я смогу
     скопировать результат в чат.
2. Пошаговая инструкция: как создать черновик в консоли Яндекс Игр, загрузить
   ZIP, открыть тестовую ссылку в Chrome на десктопе и на Android, где смотреть
   консоль на телефоне (десктоп-режим или через удалённую отладку — дай самый
   простой путь).
ПРИЁМКА: однозначный вердикт одним из двух вариантов —
«getUserMedia в iframe Яндекса работает» или «не работает, вот текст ошибки».
Никаких «возможно, заработает» — только наблюдаемый факт.
ВАЖНО: для этой проверки не нужен ни SDK-лидерборд, ни монетизация, ни ревью —
только черновик и тестовая ссылка.
```

## ПРОМТ 5. Детектор «смех / выдох / фырканье» (2–3 дня, 0 ₽)

```
{общий блок}

ЗАДАЧА 5: ДЕТЕКТОР ЗВУКОВ БЕЗ ML — ДВУХУРОВНЕВЫЙ
Цель: отличать смех, выдох и фырканье от речи и шума. Вдох НЕ детектируем —
микрофон его практически не слышит, все механики строятся на выдохе.
АРХИТЕКТУРА
Уровень 1 — каждые 50 мс, только дешёвые вычисления:
- RMS (громкость);
- огибающая сигнала со сглаживанием (экспоненциальное среднее) и её гладкость:
  гладкий медленный подъём-спад = выдох, резкие всплески = порыв/смех;
- модуляция громкости: считаем пики огибающей в секунду — ритм 4–6 Гц
  характерен для смеха/фырканья.
Уровень 2 — в конце звукового окна, правила классификации:
- СМЕХ: есть питч (оценка через zero-crossing rate или автокорреляцию в полосе
  ~100–300 Гц) + ритм пиков 4–6 Гц + длительность окна ≥ 0,4 с;
- ФЫРКАНЬЕ: питча нет + серия 1–3 коротких резких импульсов;
- ВЫДОХ: питча нет + гладкая огибающая + длительность 0,5–2 с;
- ИНАЧЕ (речь, шум, телевизор) → событие игнорируется, но логируется.
ТРЕБОВАНИЯ К ВЫВОДУ
- Для каждого распознанного события: тип, уверенность 0..1, длительность.
- Счётчики: event_detected (сколько всего), event_confidence (средняя),
  misfire_rate (доля неверных — считается по ручной разметке ниже).
- Всё логировать в консоль и дублировать на экране последней строкой.
- Калибровка как в игре: 3 секунды тишины для фона + мой максимальный звук
  задаёт 100% шкалы. Все пороги — в долях от моего персонального максимума.
- Щедрые пороги и фолбэк: если сигнал неясен, лучше «звук есть» с низкой
  уверенностью, чем пропустить событие. Ориентир точности честный: ~0,75 у
  профессиональных детекторов, дизайн должен прощать 25%.
ТЕСТ-СКРИПТ: добавь кнопку «Прогнать тест» — 5 категорий (смех, шум телевизора,
выдох, фырканье, обычная речь), я по очереди издаю каждый звук, скрипт
записывает вердикт детектора в таблицу на экране: строка = категория,
колонки = что детектор решил, уверенность, верно/неверно.
ПРИЁМКА: таблица из 5 строк заполнена, misfire_rate посчитан. Цель на этом
этапе: смех и выдох не путаются между собой и речь не принимается за смех.
Если путаются — предложи, какой параметр подвинуть (порог ритма, длину окна,
полосу питча), не переписывая всё с нуля.
```

1. Общий блок + промт — вставляются в новый чат с ИИ-программистом вместе.
2. Порядок строгий: 1 → 2 → 3 → 4 → 5. Промт 4 использует код из промта 2,
   промт 5 — код и калибровку из промта 2.
3. Результат каждой задачи фиксировать до перехода к следующей — включая
   негативный результат (особенно промт 4: вердикт «не работает» меняет
   архитектуру игры и экономит недели).
