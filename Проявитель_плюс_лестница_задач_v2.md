# Проявитель+: лестница минимальных задач с измеримыми результатами
Версия: 2 (15.11.2026). Дополнение к брифу v2. Каждая задача — «разведка»: минимум усилий, максимум информации. Каждая заканчивается вещью, которую можно ПОЩУПАТЬ (файл, экран, цифра). Правило: не переходить к следующей ступени, пока не получен результат предыдущей — даже если результат негативный. Негативный результат на ранней ступени экономит недели.

---

## Блок А. Техническая разведка (неделя 1, бюджет 0 ₽)

### Задача 1. Рабочее место (1 вечер)
**Что делать:** установить VS Code (или любой редактор), браузер Chrome/Yandex, создать аккаунт на GitHub. Создать папку проекта, файл index.html с одной строкой текста.
**Результат на руках:** страница `index.html` открывается в браузере двойным кликом или через локальный сервер.
**Провал значит:** проблема в окружении — чинить здесь, а не позже.

### Задача 2. Микрофон локально (1 день)
**Что делать:** одна страница: `getUserMedia({audio:true})` → `AudioContext` → `AnalyserNode` → расчёт RMS каждые 50 мс → вертикальная полоска громкости на экране + вывод чисел в консоль. Кнопка «Разрешить микрофон» запускает ВСЁ в одном обработчике клика (браузеры требуют жест пользователя и HTTPS для getUserMedia; локально — exception для localhost).
**Результат на руках:** полоска прыгает от голоса, в консоли сыплются числа RMS.
**Пощупать:** сказать «хи» — полоска маленькая; рассмеяться — большая.
**Провал значит:** скорее всего нет HTTPS или AudioContext не по клику. Это починяемые проблемы, не тупик.

### Задача 3. Тот же файл в Telegram Mini App (1 день)
**Что делать:** создать бота через BotFather, подключить Mini App на ссылку GitHub Pages (HTTPS бесплатно). Открыть тот же файл с полоской.
**Результат на руках:** полоска работает в WebView Telegram ИЛИ зафиксирован конкретный отказ (в каком браузере/платформе, текст ошибки).
**Факт для честности:** в Telegram камера/микрофон доступны через getUserMedia с HTTPS, но на iOS до версии 16.4 не работали вовсе; на Android разрешение может спрашиваться при каждом запуске. Это известные ограничения WebView, не ваши баги.
**Провал значит:** Telegram остаётся каналом, но тестирование идёт через GitHub Pages в браузере + RuStore-альфу.

### Задача 4. ГЛАВНАЯ РАЗВЕДКА: микрофон в iframe Яндекса (1–2 дня)
**Что делать:** создать черновик игры в консоли Яндекс Игр, загрузить минимальный ZIP (index.html в корне + тот же код микрофона). Открыть черновик по тестовой ссылке.
**Результат на руках:** однозначный вердикт — «getUserMedia в iframe Яндекса работает / не работает». Логировать ошибку в консоль и на экран.
**Почему это главная разведка:** кросс-доменный iframe по умолчанию блокирует камеру и микрофон; доступ дают только через атрибут `allow="microphone"` у фрейма, который ставит платформа, а не разработчик. Если Яндекс его не ставит — кнопочный дублёр становится основной механикой, а микрофон — флаг-фичей. Это меняет всю архитектуру, поэтому узнавать надо ДО написания раундов.
**Провал значит:** не катастрофа, а архитектурный факт. Дублёр был заложен в бриф именно на этот случай.

### Задача 5. Детектор «смех / выдох / фырканье» (2–3 дня)
**Что делать:** двухуровневый детектор. Уровень 1 (каждые ~50 мс): RMS-энергия, гладкость огибающей, модуляция 4–6 Гц. Уровень 2 (в конце окна ~1–2 сек): классификация — питч + ритм 4–6 Гц + длительность ≥ 0,4 с = смех; без питча + серия импульсов = фырканье; без питча + гладкая огибающая = выдох. Вдох не детектировать (микрофон его не слышит).
**Результат на руках:** таблица из 5 ручных тестов с критериями «валидно/провал»: смех, шум телевизора, выдох, фырканье, обычная речь. Число: доля ложных срабатываний `misfire_rate`.
**Пощупать:** открыть таблицу и увидеть, что детектор отличил смех от речи хотя бы у себя.
**Ориентир:** даже профессиональные детекторы звука дают точность ~0,75 — дизайн обязан прощать 25% (щедрые пороги, фолбэк на тап).

## Блок Б. Ядро картинки (неделя 2, бюджет 0 ₽)

### Задача 6. Серость расцветает от голоса (1 день)
**Что делать:** любое фото → canvas в двух слоях (серый + цветной). Громкость голоса стирает серый слой или поднимает насыщенность (CSS-фильтр saturate или canvas-операции).
**Результат на руками:** экран, где кадр расцветает от хохота. Показать одному человеку: «что почувствовал?». Записать ответ дословно — это первый качественный сигнал.

### Задача 7. Калибровка 20 секунд (0,5 дня)
**Что делать:** «скажи тихое „хи“» → кадр едва теплеет; «а теперь „ХА!“» → максимум = 100% шкалы. Все пороги дальше — в долях от персонального максимума.
**Результат на руках:** у вас и у 2–3 разных людей (тихий голос, громкий) пороги работают без правки кода.

### Задача 8. Пузыри из черкания + дуновение (2 дня)
**Что делать:** палец черкает по экрану → вдоль траектории появляются серые пузыри. Выдох в микрофон (гладкая огибающая без питча) → пузыри раздуваются, шевелятся и уплывают вверх.
**Результат на руках:** полный цикл «черкнул → подул → пузыри уплыли» за 30 секунд.
**Провал значит:** проверить уровень 1 детектора — выдох отличается от речи отсутствием питча.

## Блок В. Собранная сессия (неделя 3, бюджет 0 ₽)

### Задача 9. Полный контур одной сессии (3–4 дня)
**Что делать:** собрать все звенья в один конвейер: тяготы (выбор из тегов, таймер 30–40 сек) → черкание → пузыри → дуновение → лесенка хихиканья («фыркни → хихикни → сильнее») → проявка пятнами из точек разрыва → спуск (кремовый) → вопрос «теплее / спокойнее / легче / по-прежнему» → полка.
**Результат на руках:** вы прошли сессию от начала до конца сами. Потом — 2 знакомых. Засечь: время прохождения, места где бросались/задумывались, сколько раз сработал дублёр.
**Пощупать:** работающая сессия на GitHub Pages — ссылку можно давать любому.

### Задача 10. Аналитика (1 день)
**Что делать:** консоль логов событий: session_start, permission_mic_result, permission_camera_result, calibration_done, round_result, event_detected, event_confidence, misfire_rate, fallback_used, mood_selected, descent_breaths, survey_before_score, survey_after_score, survey_skipped.
**Результат на руках:** открытая таблица событий — видно каждое действие тестера.
**Правило честности:** аудио не сохраняется и не отправляется; в аналитику — только числа и коды тегов, никогда тексты и изображения.

## Блок Г. Валидация с людьми (недели 4–5, бюджет 0 ₽)

### Задача 11. 10–15 тестеров (5–7 дней)
**Что делать:** волна 1 — 10–12 личных сообщений знакомым (максимум треть выборки). Скрининг-анкета 4–5 вопросов: привычка самопомощи + частота игр. Ссылка на GitHub Pages / Telegram.
**Результат на руках:** сырые цифры по главным гипотезам:
- ≥ 50% дошедших до геймплея реально смеются вслух (детекция по калиброванному максимуму);
- ≥ 2 смен громкости у медианы внутри раунда;
- конверсия в разрешение микрофона ≥ 90% десктоп / не ноль мобильный;
- ≥ 40% выбрали «легче / спокойнее / теплее» после сессии.
**Пощупать:** таблица, где каждая строка — человек, каждый столбец — факт.
**Провал значит:** именно то, ради чего затевался валидатор. Гипотеза не подтвердилась = сэкономлены месяцы разработки «Хохотка». Это успех разведки, а не провал проекта.

### Задача 12. Замер «стало легче» (параллельно с задачей 11)
**Что делать:** шкала 0–10 («очень тяжело» … «очень хорошо») до входа и после титров. Всегда кнопка «Пропустить».
**Результат на руках:** дельта до/после по каждому тестеру + доля пропустивших.
**Честная граница:** это сигнал, а не доказательство. Малая выборка (30–50), самоотбор, эффект ожидания — результаты требуют проверки на большей выборке. Не формулировать их как «доказано наукой».

## Контрольная точка Go/No-Go (конец недели 5)

Идти дальше к «Хохотку» стоит при одновременном выполнении:
1. Микрофон в iframe Яндекса работает (или принято решение строить на дублёре).
2. `misfire_rate` ≤ 15% на пяти ручных тестах.
3. ≥ 50% тестеров смеялись вслух.
4. ≥ 40% вышли в «легче/спокойнее/теплее».
5. Никто не назвал сессию неприятной (нулевая негативная тональность отзывов).

Если хотя бы два пункта провалены — вернуться к механике, а не «докрутить маркетинг»: провал либо в детекторе (задача 5), либо в эмоциональном контуре (задача 9).

## Сводка: что пощупать в конце каждого блока

| Блок | Вещь на руках | Ключевая цифра |
|---|---|---|
| А | ZIP с полоской громкости + вердикт по iframe + таблица детектора | misfire_rate ≤ 15% |
| Б | Экран «серость → цвет» и «черкнул → подул → уплыло» | калибровка у 3 людей без правок |
| В | Работающая сессия со ссылкой | время прохождения, число фолбэков |
| Г | Таблица тестеров + дельта настроения | ≥ 50% смеялись; ≥ 40% «легче» |

## Честные риски, о которых нельзя забывать
- Микрофон в iframe Яндекса — единственный риск, который может обнулить всю микрофонную механику. Проверяется первым из всех.
- iOS Safari: DeviceOrientationEvent требует requestPermission() строго по тапу; getUserMedia требует жеста и HTTPS.
- Точность любого детектора ~0,75 — 25% ситуации детектор распознает неверно, дизайн обязан это прощать.
- Цифры валидатора — сигнал, не доказательство: малая выборка, самоотбор, эффект ожидания.
- Модерация Яндекса: ~3–5 рабочих дней, отправлять только полностью собранное; короткий контент без мотивации перепроходить снимают с публикации.
