## Промт 9. Полный контур одной сессии (3–4 дня, 0 ₽)

```
{общий блок}

ЗАДАЧА 9: СБОРКА ПОЛНОГО КОНТУРА СЕССИИ
У нас уже есть работающие куски: микрофон с RMS (задача 2), калибровка (задача 7),
расцвет кадра от голоса (задача 6), пузыри из черкания и дуновение (задача 8),
детектор смех/выдох/фырканье (задача 5). Теперь собираем их в один непрерывный
контур сессии от входа до полки. Ничего нового не изобретаем — только склейка
и недостающие экраны.

АРХИТЕКТУРА
Один файл session.html (или маленький набор файлов). Экраны — состояния одной
машины состояний (state machine), переходы по событиям детектора или кнопкам
дублёра. Тексты — заглушки на русском, пометь их в коде комментарием
«// ЗАГЛУШКА: правится» — их буду править я, без тебя.

СОСТАВ СЕССИИ (строго по порядку, ~3–5 минут):
1. ВХОД. Один экран-объяснение: «Сейчас браузер спросит про микрофон — он нужен,
   чтобы задувать пузыри. Можно играть и без него». Кнопки «Разрешить» /
   «Без микрофона» (отказ неунизителен). Системный промпт — только после тапа.
2. КАЛИБРОВКА. Готовый код из задачи 7, без изменений.
3. ТЯГОТЫ ДНЯ (30–40 секунд, таймер виден игроку). Экран «Что тебя тяготит
   сегодня?» — 8–10 готовых тегов (начальник, дорога, деньги, усталость, ссора,
   новости, учёба, здоровье — редактируемые константы) + опциональное свободное
   поле. Выбор НЕ обязателен: кнопка «Пропустить» должна быть заметной.
   После выбора — переход к черканию, руминация ограничена таймером.
4. ЧЕРКАНИЕ → ПУЗЫРИ → ДУНОВЕНИЕ. Готовый код из задачи 8. Пузыри без надписей.
5. ЛЕСЕНКА ХИХИКАНЬЯ (титрование). Игра ведёт по ступеням, НЕ требуя веселья:
   «Фыркни» → детектор задачи 5 ловит фырканье → «Хихикни» → «Сильнее» → смех.
   Подсказки нарастают: пока игрок дышит — дуновение качает пузыри; когда
   детектор поймал первый смех — один маленький бабл становится полупрозрачным,
   радужным и ЛОПАЕТСЯ (лопаются только баблы от смеха; от выдоха — уплывают,
   это разные события). Пропустить ступень нельзя, но застрять на ней можно
   сколько угодно — следующая открывается по факту распознанного звука.
6. ПРОЯВКА. Цвет расползается ПЯТНАМИ из точек лопнувших баблов (не мгновенно
   и не равномерно): каждый лопнувший бабл сеет очаг цвета, пятна растут
   со временем (константа скорости в начале файла). Серый слой сцены из
   задачи 6 вытесняется по мере покрытия пятнами.
7. СПУСК (~30 секунд). Все механики гаснут, остаётся только «подуй ещё»:
   каждое дуновение мягко смягчает экран к тёплому кремовому. Без смеха,
   без целей, без счёта. Событие descent_breaths (число дуновений).
8. ВОПРОС. Только после спуска, никогда на пике. «Как ты сейчас?» — четыре
   кнопки: «теплее / спокойнее / легче / по-прежнему». Без «правильного» ответа.
   Ветка «по-прежнему» — тёплая заглушка: «Сегодня так. Кадр всё равно остался
   с тобой». Порядок кнопок рандомизируй при каждом показе.
9. ПОЛКА. Кадр уезжает на стилизованную полку, полка чуть светлеет.
   Кнопка «Сыграть ещё раз» — цикл повторяется с шага 3 (калибровку не повторять).

ФУЛБЭК КРИТИЧЕН: на каждом шаге с микрофоном должна работать кнопка-дублёр
(тап вместо выдоха, зажатие вместо смеха). Человек с отказавшим микрофоном
обязан пройти сессию целиком до полки. Событие fallback_used логируй на каждом
шаге отдельно.

ПРИЁМКА:
1. Ссылка на GitHub Pages открывается с телефона и с десктопа.
2. Полную сессию можно пройти и с микрофоном, и без него.
3. Я засекаю время прохождения и записываю места, где сам споткнулся или
   захотел бросить — эти места пойдут тебе на правку.
ЧАСТЫЕ ПРОВАЛЫ: переходы экранов «моргают» при смене состояния — делай мягкие
фейды (0,3–0,5 с), а не мгновенные show/hide; таймер тягот сбрасывает прогресс —
проверь, что таймер только переводит на следующий шаг, ничего не обнуляя.
```

## Промт 10. Аналитика без бэкенда (1 день, 0 ₽)

```
{общий блок}

ЗАДАЧА 10: ЛОГ СОБЫТИЙ И ЭКСПОРТ ДАННЫХ
Сессия из задачи 9 работает. Нужна аналитика без сервера: ноль бюджета, поэтому
никаких внешних сервисов — всё в localStorage + экспорт в файл.

ТРЕБОВАНИЯ
1. Модуль log.js, встраиваемый в session.html: функция logEvent(name, params),
   которая пишет в localStorage строку формата: id_сессии, метка времени
   (мс от старта сессии), название события, параметры JSON.
   id_сессии — случайная строка, генерируется при каждом заходе.
2. События (минимальный набор для задач 11–12 лестницы):
   session_start, permission_mic_result (granted/denied/error),
   calibration_done (фон, максимум), calibration_retried,
   tags_shown, tags_selected (ТОЛЬКО коды тегов, например tag_3 — никогда
   свободный текст), tags_skipped, scribble_duration_ms,
   bubble_spawned, bubble_released, bubble_popped,
   exhale_started, exhale_ended (длительность),
   ladder_step_reached (какая ступень), laugh_detected, snort_detected,
   event_detected, event_confidence, misfire_rate,
   fallback_used (шаг сессии, на котором сработал дублёр),
   manifestation_started, manifestation_complete,
   descent_breaths, mood_selected (код варианта), mood_screen_shown,
   shelf_reached, session_end (длительность сессии),
   survey_before_score, survey_after_score, survey_skipped.
3. Экспорт: на экране полки — незаметная кнопка «Скачать лог» → файл
   sessions.csv с заголовком колонок. Двойная кнопка не нужна, файл —
   только по явному действию разработчика (меня).
4. Приватность, вшить неукоснительно: аудио не сохраняется и не отправляется;
   в лог не пишутся тексты тегов, любые изображения и любые слова игрока —
   только числа и коды. Подпиши это комментарием в log.js.
5. Документация: рядом с кодом — таблица «событие → что значит → как читать
   в анализе». Я буду рассылать её тестерам вместе со ссылкой.
6. Защита от переполнения: localStorage вмещает ~5 МБ — при превышении
   не падаем, а удаляем самые старые сессии и пишем предупреждение в консоль.
ПРИЁМКА: я прохожу 2 сессии (одну с микрофоном, одну на дублёре), скачиваю
CSV — и в файле видно каждое моё действие по строкам, включая оба
fallback_used. В файле нет ни одного слова, которое я вводил с клавиатуры.
ЧАСТЫЕ ПРОВАЛЫ: события дублируются при быстрых переходах экранов — ставь
антидребезг (одно событие не чаще раза в 200 мс, кроме явно потоковых);
CSV ломается на запятых в параметрах — экранируй или используй точку с запятой
как разделитель, зафиксируй выбор в документации.
```

## Как этим пользоваться

1. В новый чат с ИИ-программистом вставляете общий блок + один промт.
2. Промт 9 — самый большой в проекте. Если программист утонет, разбейте на
   полусловы: сначала шаги 1–4 (вход → черкание), потом шаги 5–7 (лесенка →
   проявка → спуск), потом шаги 8–9 (вопрос → полка). Лучше три маленьких
   срабатывания, чем одно огромное.
3. Промт 10 запускать, когда контур уже живой: логировать нечего в пустой сессии.
4. Шпаргалка по приёмке: фиксируйте ДОСЛОВНО, что показывает экран при ошибке —
   это главный товар для следующего запроса программисту.
